# AXNOVATECH V78.3 — Photography and UX fix

## What changed
- Fixed the core image resolver bug: Pixabay media-setup downloads `.jpg`, while the old resolver only looked for `.webp`.
- Resolver now checks exact slot `.jpg`, `.jpeg`, `.webp`, and `.png` assets before using fallbacks.
- Exact content slots now resolve to their own image rather than repeatedly reusing a handful of generic photos.
- Replaced the four text-only capability boxes with large photographic cards and richer enterprise copy.
- Added dedicated Pixabay search slots for strategy, product experience, engineering, and cloud/security.
- Made the brand film visible and user-playable with native video controls.

## Required local setup
Copy your existing `apps/web/.env.local` (containing `PIXABAY_API_KEY`) into this release. Do not commit or share that file.

From the repository root run:
```bash
npm ci
npm run media:setup -- --soft
npm run qa:source
npm run check:media -w @axnovatech/web
npm run dev:web
```

Pixabay requires downloading photos to your own server for permanent use; this project stores them under `apps/web/public/photos` and videos under `apps/web/public/videos`. API use is cached for 24 hours and is rate limited. See https://pixabay.com/api/docs/.
